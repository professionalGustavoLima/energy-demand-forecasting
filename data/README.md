# Data Pipeline Overview

The data pipeline retrieves scheduled electricity load data from the ONS API and progressively transforms it through three data layers:

```text
ONS API → Raw Data → Trusted Data → Refined Data
```

Each layer has a specific responsibility, from raw data extraction to cleaning and preparation for analysis and modeling.

---

## 1. Raw Data — `I_raw`

### Source and Retrieval

**API:** [ONS Carga Programada API](https://apicarga.ons.org.br/prd/cargaprogramada)

**Load areas:**

* `SECO` — Southeast/Central-West
* `N` — North
* `NE` — Northeast
* `S` — South

**Date range:** `2020-01-01` to `2026-06-30`

The extraction is implemented by `ONSDataloader` in:

`data/I_raw/load_data.py`

### API Requests

The requested period is divided into **6-month intervals** to avoid large API requests.

Each request is specific to one load area and one date interval:

```text
https://apicarga.ons.org.br/prd/cargaprogramada
    ?dat_inicio={START_DATE}
    &dat_fim={END_DATE}
    &cod_areacarga={LOAD_CODE}
```

The API response is returned as JSON and converted into a pandas DataFrame.

### Retry Strategy

Each API request supports:

* Maximum of `3` attempts
* Request timeout of `60` seconds
* `5` seconds between failed attempts

If all attempts fail, the pipeline raises a `RuntimeError`.

### Raw Data Consolidation

Data retrieved from all load areas and time intervals is concatenated into a single DataFrame using:

```python
pd.concat(dataframes, ignore_index=True)
```

The resulting dataset is saved as:

`data/I_raw/raw_data.parquet`

---

## 2. Trusted Data — `II_trusted`

### Transformation

The raw data is transformed by `ONSTrustedData` in:

`data/II_trusted/transform_data.py`

The transformation consists of two main steps:

1. Convert the dataset from **long format to wide format**.
2. Rename columns according to the trusted data schema.

### Long to Wide Transformation

The raw dataset contains one row per load area and timestamp.

The data is pivoted using:

* `dat_referencia`
* `din_referenciautc`
* `cod_areacarga`
* `val_cargaglobalprogramada`

Each load area becomes a separate column.

### Column Mapping

| Raw Column          | Trusted Column                               |
| ------------------- | -------------------------------------------- |
| `dat_referencia`    | `ref_date`                                   |
| `din_referenciautc` | `ref_datetime`                               |
| `N`                 | `north_scheduled_load_mwmed`                 |
| `NE`                | `northeast_scheduled_load_mwmed`             |
| `S`                 | `south_scheduled_load_mwmed`                 |
| `SECO`              | `southeast_centralwest_scheduled_load_mwmed` |

The resulting trusted dataset is saved as:

`data/II_trusted/trusted_data.parquet`

---

## 3. Refined Data — `III_refined`

### Transformation

The trusted data is cleaned and prepared for analysis by `ONSRefinedData` in:

`data/III_refined/refine_data.py`

The refined layer applies the following transformations:

1. Remove rows with excessive missing values.
2. Align the dataset to the valid analysis period.
3. Standardize timestamps to São Paulo local time.
4. Detect and remove outliers using the IQR method.
5. Interpolate missing load measurements.
6. Select the final refined data schema.

### Missing Value Filtering

Rows are removed when fewer than **three of the four load measurements** are available.

The load columns considered are:

* `north_scheduled_load_mwmed`
* `northeast_scheduled_load_mwmed`
* `south_scheduled_load_mwmed`
* `southeast_centralwest_scheduled_load_mwmed`

This prevents periods with insufficient information from being used in subsequent processing.

### Datetime Standardization

The original `ref_datetime` values are interpreted as UTC timestamps and converted to:

```text
America/Sao_Paulo
```

The timezone information is then removed, leaving a local naive datetime.

The `ref_date` column is subsequently regenerated from the standardized `ref_datetime`.

### Outlier Treatment

Outliers are detected independently for each load area using the **Interquartile Range (IQR)** method.

For each load variable:

```text
IQR = Q3 - Q1

Lower Bound = Q1 - 1.5 × IQR
Upper Bound = Q3 + 1.5 × IQR
```

Values outside these bounds are considered outliers and are replaced with `NaN`.

The outlier values are not directly deleted. Instead, they are converted into missing values so they can be handled by the subsequent interpolation step.

### Missing Value Interpolation

Missing load measurements generated by the outlier treatment, as well as existing missing values, are filled using **time-based linear interpolation**.

The interpolation is limited to a maximum of:

```text
48 measurements
```

Since the dataset has a **30-minute frequency**, this corresponds to:

```text
48 × 30 minutes = 24 hours
```

Therefore, gaps of up to **24 hours** can be interpolated.

### Final Schema

The refined dataset contains:

* `ref_date`
* `ref_datetime`
* `north_scheduled_load_mwmed`
* `northeast_scheduled_load_mwmed`
* `south_scheduled_load_mwmed`
* `southeast_centralwest_scheduled_load_mwmed`

The resulting dataset is saved as:

`data/III_refined/refined_data.parquet`

## Summary

The complete data pipeline can be summarized as:

```text
ONS API
  ↓
Raw Data
  ↓
Long → Wide
  ↓
Column Standardization
  ↓
Trusted Data
  ↓
Missing Value Filtering
  ↓
Datetime Standardization
  ↓
IQR Outlier Detection
  ↓
24h Time-based Interpolation
  ↓
Refined Data
```

The **Raw** layer preserves the data retrieved from the ONS API, the **Trusted** layer standardizes its structure and schema, and the **Refined** layer performs the cleaning and preprocessing required for subsequent exploratory analysis and forecasting tasks.
